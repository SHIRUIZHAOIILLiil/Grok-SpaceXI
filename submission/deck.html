06MethodDETERMINISTIC

How a case closes

Numbers first, then documents, then IDs.

01

Read the measurement

The alert carries structured values: £19,212.04, 30 days, Lebanon, limit £5,000.

02

Find the money

Search the customer’s file for a document whose amount reconciles with the alert.

03

Test for contradiction

Wrong payee, wrong date, wrong goods, a dissolved company: the close is refused.

04

Cite what decided it

Every verdict names the document and transaction IDs it rests on — checkable by hand.

No explanation found → ESCALATE. The system never guesses a close.

1:15 · 四步快带，重点是第 4 步和最后那句"never guesses"。
07RubricWHAT IS SCORED

How we read the rubric

Verdicts, reasons, and the same answer twice.

60%

Unseen cases. Verdicts cost more than reasons: a wrong close is 10, a needless escalation 3.

20%

Development cases, re-run to prove the answers came from the system rather than a lookup.

20%

Reproducibility across five runs. This is why a model never decides a verdict.

Measured on all 4,000 cases

  • validate: 0 errors, 0 warnings
  • 5 runs × 4 institutions: byte-identical
  • 5.5 s for the full set, 1.4 ms per case

What we refuse to do

  • Never close on a single shared detail
  • Never treat a prior review as evidence
  • Never ask the customer once there is suspicion
1:30 · 20% 那格停一下：这是我们不用模型做判定的全部理由。
08ModelBOUNDARY

Where the model is — and is not

The verdict is deterministic. The model reads prose.

What it does

  • 46 of 140 gift letters state a birth date in a sentence, not a field
  • It returns a verbatim quote — nothing else
  • The quote must occur in the document, character for character

What it never does

  • Choose a verdict or a reason code
  • Name a document that is not in the case
  • Run when the key is missing — output stays byte-identical

Measured on all 4,000 cases: the model changed 0 verdicts.

1:40 · 这句话是全场最值钱的一句：我们知道什么时候不该用模型。
