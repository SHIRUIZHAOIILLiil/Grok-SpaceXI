# The data

## Where it comes from

The official Track 1 package, downloaded from the event page's "Get the dataset" link
(`hackathon.zip`, 22,107,183 bytes). It is not generated by us and it is not committed: the
organisers' terms keep it to participants, so it lives in `data/` and `data/` is gitignored.

Every customer, company, account and document in it is invented (`BRIEF.html`).

## What each file gives you

- `alerts.jsonl` — `rule_id`, `rule_name`, `message` (prose with amounts, dates, countries,
  counterparties), `measured` (structured values), `transaction_ids`. **The alerts are pre-generated;
  implementing TM01–TM22 is not part of the task.**
- `cases.jsonl` — the customer, the review window, the alert ids in the case, any held payment.
- `customers.jsonl` — identity, occupation, address, risk rating, and the declared profile the alert
  is measured against.
- `transactions.jsonl` — booked_at, direction, channel, amount, counterparty name/account/country.
- `evidence.jsonl` + `evidence/*.md` — the documents, with a semi-structured header
  (`**Document ID:**`, `**Dated:**`, …).
- `internal_list.jsonl` — earlier internal cases, exited customers, blocked banks.
- `previous_reviews.jsonl` — earlier reviews. Every one in the development set was closed. The policy
  says a prior review covers only what it describes, so these are context, never a ground to close.

## Two things the data does that will bite you

**Document ids repeat across institutions.** `BKG-3143` exists in more than one folder. Any join on
`doc_id` alone silently mixes institutions — the audit tables key on `(institution, doc_id)` for
this reason.

**`measured` is not uniform.** TM01 gives `received_gbp`/`baseline_gbp`/`multiple`, TM03 gives
`count`/`total_gbp`/`locations`, TM22 gives `list_entry`/`matched_on`/`matched_party`, TM10 gives
`fund`/`held_days`/`bought_gbp`. The decision table reads the keys each rule actually has; the prose
`message` is the fallback.

## What the development set does not have

Answers. There are no labels, so accuracy cannot be measured locally. `tools/labels.json` holds
pseudo-labels inferred from evidence combinations — useful for spotting disagreements, not truth.
The score that matters comes from 800 unseen cases.
